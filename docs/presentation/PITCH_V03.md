# Clinical Compass v0.3 — содержание слайдов для грантовой заявки

> Источник исходников: текущий локальный репозиторий `clinical-compass` на `60b3802` с интегрированным патчем v0.3. Изображения — прежний демонстрационный стенд, не клинический пилот.

## 1. Архитектура

**Пациент (Flutter)** → **Backend (FastAPI)** → **AI extraction (GigaChat)** → **Patient State (PostgreSQL)** → **Rule Engine (детерминированные правила)** → **Пациент / врач**.

- Модель выделяет симптомы, приём препаратов, сигналы риска, лабораторные упоминания.
- Правила определяют `doctor_priority` и `patient_action`, но не сама LLM.
- При недоступности внешней модели работает ограниченный локальный словарь красных флагов; это не полная замена LLM.
- Экстренные уведомления по шаблонам, без свободно генерируемых советов.
- Интеграция ЕМИАС/1С пока демонстрационная, нет подтверждённого промышленного подключения.

## 2. Что получает пациент

- Опросники GAD-7/PHQ-9, запись симптомов и отметки приёма препаратов.
- История сообщений, контакты с врачом, важные уведомления.
- Новый блок `Мой прогресс`: 7 дней заполнения дневника, без игровых наград за «хорошее» здоровье.

Скриншот baseline: `docs/screenshots/patient-home.jpg` (до редизайна v0.3).

## 3. Что получает врач

- Очередь событий с приоритетами; срочные события закреплены до принятия в работу.
- Карточка пациента, история, факт и причина алерта — кнопка «Почему?».
- Решение врача остаётся за специалистом; система не назначает и не отменяет лечение.

Скриншот baseline: `docs/screenshots/doctor-queue.jpg`.

## 4. Метрики извлечения — не клиническая точность

**В презентации используется только финальный набор чисел после медицинской сверки.**

Файл `evaluation/results/gigachat_v1_2_medical_rc1/metrics.json` проверен 02.11.2026 и включён в эту ветку: 155 сообщений, **183** сущности, TP 142, FP 82, FN 41, Precision 0.634, Recall 0.776, F1 0.698. Это сверка сохранённого результата, а не повторный запуск модели. Архивный прогон на 172 сущностях в слайды не включён.

Оба прогона измеряют **извлечение фактов**, не качество медицинских решений. 8/8 отдельно выбранных опасных примеров — техническая проверка, не доказательство клинической безопасности.

## 5. Следующий этап

Медицинская экспертиза текстов и правил → дополнительные негативные и пограничные примеры → пилот на согласованной группе → юридические/ИБ проверки → интеграция с реальной МИС при доступности API и договорённости с клиникой.

## Требования перед релизом

- Перед публичным использованием сверить происхождение и версию сохранённого финального прогона с командой модели.
- Сделать актуальные скриншоты после сборки Flutter и проверить читаемость 320/390/768/1440 px.
- Утвердить тексты для пациента с врачом.
- Не утверждать клиническую эффективность без клинической валидации.

Для пересборки слайдов: `cd scripts && npm install && npm run build:pitch`. Скрипт берёт финальные метрики из `evaluation/results/gigachat_v1_2_medical_rc1/metrics.json`.
