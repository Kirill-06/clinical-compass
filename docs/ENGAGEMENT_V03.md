# Вовлечение пациента v0.3 — безопасный MVP

## Что реализовано

- Backend GET `/patients/{patient_id}/dashboard` возвращает дополнительное поле `engagement`.
- За последние 7 календарных дней клиники рассчитывается **количество дней с записями**.
- Источники: законченные пациентом опросники, отметки приёма препарата и записи о симптомах, введённые через форму.
- Все записи за один день дают **один** активный день. За 1/3/5 активных дней отображается необязательное достижение.
- Пациент видит 7-дневную полосу с читаемыми отметками, без сравнений с другими людьми.
- Прогресс рассчитывается из существующих медицинских данных при чтении, без новых таблиц БД или фоновых заданий.

## Медицинские ограничения

1. Статусы `taken` и `missed` **одинаково** считаются записью. Нельзя поощрять ложную отметку «принял».
2. Нет очков за низкий балл по PHQ-9/GAD-7, отсутствие симптомов, отмену препаратов или изменение лечения.
3. Никакого влияния на `RuleEngine`, `patient_action`, `doctor_priority`, Patient State или алерты.
4. `days_with_entries` **не является** adherence, клинической оценкой состояния или мерой эффективности лечения.
5. Доступ по тем же patient-self правилам, что и к основному dashboard; показатели не доступны другим пациентам.
6. На главной есть необязательная поддерживающая подсказка с нейтральной иллюстрацией-иконкой. Пациент может скрыть её; выбор сохраняется локально. Текст не содержит медицинских рекомендаций.

## Формат API

```json
{
  "engagement": {
    "window_days": 7,
    "days_with_entries": 3,
    "days": [
      {"date": "2026-10-15", "has_entry": false},
      {"date": "2026-10-16", "has_entry": true}
    ],
    "achievement": {"id": "three_days", "title": "Три дня с записями"},
    "explanation": "Считаем только дни с записями, а не состояние здоровья или соблюдение лечения."
  }
}
```

Список `days` в этом отрывке сокращён; настоящий API возвращает ровно 7 объектов.

## Тестирование

`PYTHONPATH=backend/src:backend/tests pytest backend/tests/test_engagement.py -q`

Проверяем уникальность по дате, границы окна, отсутствие записи, достижения, защиту доступа и отсутствие побочных эффектов чтения для очереди врача.

## Следующая итерация (не реализовано)

- Проверка понятности блока с пациентами и врачами.
- Проверка понятности подсказки и блока прогресса с пациентами.
- Аккуратные напоминания с пользовательской настройкой и проверкой нагрузки.
